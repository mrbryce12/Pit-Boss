# Pit Boss – project notes for Claude

Read this first. It explains what this repo is, how it runs, and the rules for changing it.

## What this is
Pit Boss is a Discord bot for the **Blue Chip** fantasy football league on MyFantasyLeague (MFL).
- League ID: `27743`, season `2026`, host `https://www48.myfantasyleague.com`
- League home: https://www48.myfantasyleague.com/2026/home/27743
- 32 teams, dynasty format with IDP (positions include DE, DT, LB, CB, S), salaries/contracts, taxi squad, IR, blind-bid waivers, future draft picks.
- Discord channel for automated posts: `#league-activity`

The people maintaining this are not professional developers. Keep code simple, standard-library-first, well commented, and give step-by-step, plain-English instructions for any setup change.

## Secrets (never commit these)
- `DISCORD_WEBHOOK_URL` – GitHub Actions secret, used by `pitboss.py`.
- `MFL_API_KEY` – optional GitHub secret; only needed if the league becomes private.
- **Anthropic API key** – in `anthropic_key.txt` next to `pitboss_bot.py` (git-ignored) or the `ANTHROPIC_API_KEY` env var. No key = AI chat off, slash commands still work.
- Discord **bot token** – in `token.txt` next to `pitboss_bot.py` (git-ignored) or the `DISCORD_BOT_TOKEN` env var on a server.

If a token or webhook URL ever gets committed or pasted somewhere public, reset it immediately (Discord Developer Portal → Bot → Reset Token; or delete/recreate the webhook).

## MFL API notes (verified against this league)
Base: `{HOST}/{YEAR}/export?TYPE=<type>&L=27743&JSON=1` – public for this league, no login needed.
- `transactions` (`DAYS=n`): types seen: `TRADE`, `FREE_AGENT`, `BBID_WAIVER`, `IR`, `LOCK_ALL_PLAYERS`, `UNLOCK_ALL_PLAYERS`, `BBID_AUTO_PROCESS_WAIVERS`.
  - TRADE: `franchise`, `franchise2`, `franchise1_gave_up`, `franchise2_gave_up` (comma-separated, trailing comma), `comments`, `by_commish`.
  - FREE_AGENT: `transaction` = `"added,|dropped,"`. BBID_WAIVER: `"added,|bid|dropped,"`.
  - IR: `activated`, `deactivated`.
  - Pick codes: `FP_<franchise>_<year>_<round>` (future), `DP_<round0>_<pick0>` (current year, 0-based), `BB_<amount>` (blind-bid dollars).
- `leagueStandings`: already sorted; fields `h2hwlt`, `pf`, `pa`, `pp` (potential points), `eff`, `strk`, `salary`.
- `playerScores` (`W=YTD` or week number, `POSITION`, `COUNT`, `PLAYERS`): sorted desc; `isAvailable` = "1" for free agents.
- `league` → `league.franchises.franchise[]` (id, name). `rosters` → `rosters.franchise[].player[]` (id, status ROSTER/TAXI_SQUAD/INJURED_RESERVE, salary, contractYear, contractInfo, contractStatus, drafted). **In this league `contractInfo` = YEARS REMAINING and `contractYear` = ORIGINAL contract length** (e.g. Diggs: contractYear 3, contractInfo 2). Always use `contractInfo` for analysis. **Season rollover:** every player salary escalates 20% (rule book 9k), the overall cap grows 5% (`CAP_ESCALATION`, rule 8d), IR players count 100% because everyone must leave IR by April 1 (rule 4h; taxi stays 25%, rule 11e), franchise-tagged deals are flagged as estimates (9k exception), and every years-remaining drops by 1 (contracts at 0 expire). Next-season analysis applies this (`SALARY_ESCALATION` in `pitboss_ai.py`); this-season questions use current data as-is. `players` → names are `"Last, First"`.
- A single result may come back as an object instead of a list – always normalize (`as_list`).
- `nflSchedule` (`W=week`, blank = current week) must be fetched from `https://api.myfantasyleague.com` **without** `L=` (with `L=` it redirects to the league host, which refuses it). `matchup[]` → `kickoff` (Unix time), `team[]` (`id`, `isHome`). Used by `/topscorers` to map NFL teams to game windows (TNF, Sunday intl/early/late, SNF, MNF, other); it shows the top 5 per position in `SCORER_POS` (Team QB/K/P excluded).
- Positions in this league: Team QB/K/P are `TMQB`/`TMPK`/`TMPN` (not QB/PK/PN). Some team names contain HTML `<font>` tags – `mfl.teams()` strips them.
- League rules (from `league` export): `rosterSize` 45 (active only), `taxiSquad` 10, `injuredReserve` 20, `salaryCapAmount` 1795.90, `includeTaxiWithSalary`/`includeIRWithSalary` = 25 (% of taxi/IR salary that counts), `rosterLimits` (`"0-0"` = no limit; TMQB/TMPK/TMPN max 1), `starters` (21, per-position ranges), `partialLineupAllowed` NO.
- Cap total = active salaries + 25% of taxi/IR salaries + `salaryAdjustments` (dead money) for the franchise. This matches MFL (several teams sit within $1 of the cap).
- `weeklyResults` (`W`) → `matchup[].franchise[].starters` (comma list) = submitted lineup. `injuries` (current week) must come from `API_HOST`; statuses include Out, IR, IR-R, IR-PUP, IR-NFI, Suspended, RETIRED, Holdout, Questionable, Doubtful.
- `/rosteralerts` (roster + lineup, all teams) and `/rosterviolations` (illegal rosters, all teams) share `send_roster_report()` / `find_violations()`; passing `lineups={}` = roster rules only.
- These reports only check the **current** week – MFL rosters and injuries are "as of now", so past weeks would give false alarms.
- **Playoff format (league rule book §6, https://godfather-fantasy-football.ueniweb.com/about-us):** 12 teams, Weeks 14–17. Seeds 1–4 = the 4 division winners ordered by record (Week 14 bye); seeds 5–12 = next-best records; reseeded each round (highest seed plays lowest). Tiebreakers: we use MFL `leagueStandings` order (`standingsSort` = PCT, PTS, H2H, DIVPCT…). Note MFL's `playoffBrackets` export only shows an 8-team bracket starting Week 15 – the rule book is the source of truth. Divisions: `league.franchises.franchise[].division` → `league.divisions.division[]` (names like "Div 1 - SEC"); realigned every season.
- **Draft lottery (rule book §14b):** non-playoff draft order is by Potential Points (`pp`); the 8 lowest-PP non-playoff teams (ranks 25–32) get 8,7,…,1 lottery balls for picks 1.01–1.08. `/potentialpoints` uses `playoff_picture()` to exclude teams currently in the playoffs.
- `tradeBait` → `tradeBaits.tradeBait[]`: `franchise_id`, `willGiveUp` (comma list of player ids, may include FP_/DP_ pick codes), `inExchangeFor` (free text), `timestamp` (last update). Teams with nothing posted are missing or blank. `tradebait_embed()` in `pitboss_bot.py` builds the one-team card – reuse it for auto-posting (TODO #14).
- **IR eligibility (rule book §4b–c, §13h):** only players whose MFL `injuries` status is IR, IR-R, IR-PUP, IR-NFI or Suspended may be on IR; team positions (TMQB/TMPK/TMPN) never. If the designation is lifted the owner must activate or cut. `ir_ineligible()` + `/ircheck`; activating moves the cap hit from 25% to 100%.
- **Standard reports** (bottom of `pitboss_bot.py`): `current_week()` = `nflSchedule` week; `week_games()` / `season_games()` read `weeklyResults` (`score`, `opt_pts` = best possible lineup, `result`). `weeklyResults` has **no scores for the current week** until it is final – `/matchups` uses `liveScoring` (`matchup[].franchise[]` `score`, `playersYetToPlay`) for live scores. `/recap` and `/powerrankings` default to the last completed week (current − 1).
- `/capnextyear` uses `SALARY_ESCALATION` / `CAP_ESCALATION` from `pitboss_ai.py` and the same rollover as `league_cap_table(next_season=True)` (verified identical). `/capspace` = `team_payroll()` (verified vs `league_cap_table()`).
- `/trades`: `transactions` with `TRANS_TYPE=TRADE` and no `DAYS` returns the whole league year (since late Feb). Commissioner reversals (`by_commish` = 1) count as trades.
- `/owneractivity` reads `/fflnetdynamic{YEAR}/{L}_visitors.xml` (same as the AI's `owner_activity`); admin-only via `default_permissions(manage_guild=True)` and replies privately. `INACTIVE_DAYS` = 7.
- **Saturday lineup reminder:** `lineup_reminder_loop` (every 5 min, started in `on_ready`) posts `build_roster_report()` to `LINEUP_REMINDER_CHANNEL` ("league-activity") on `LINEUP_REMINDER_DAY`/`HOUR` (Sat 7 PM CT) during the season; last post date saved in `data/lineup_reminder.json` so it posts once. `/lineupreminder` (admins) forces a post. `send_roster_report()` is now a thin wrapper around `build_roster_report()`.
- Other useful exports for the backlog: `tradeBait`, `injuries`, `nflSchedule`, `schedule`, `rules`, `liveScoring`.
- Send a descriptive User-Agent; don't poll faster than needed (cache 5–10 min).

## AI chat notes
- Models: `claude-haiku-5-5` (default) and `claude-sonnet-5-5` (when the message matches `TRADE_WORDS`). Settings at the top of `pitboss_ai.py` (daily cap, cooldown, allowed channels).
- Tools call the same `mfl` cache and helpers as the slash commands (`find_team`, `playoff_picture`, `games_back`, …) via the `globals()` passed to `setup()`. Keep those helper names stable or update `pitboss_ai.Brain`.
- Rule book: fetched from https://godfatherfantasyfootball.com/about-us (that site also links other Godfather leagues – only the text from "Blue Chip Dynasty - 32 Team" to the last "Leaguesafe Site" is kept), refreshed daily, split into sections 1–20 (+99 commissioner notes). Sections contain their own numbered lists, so a line only starts a section if it is the next number and ≤70 chars.
- Uses the privileged **Message Content Intent** (`intents.message_content = True` in `pitboss_bot.py`; must also be ON in the Developer Portal > Bot). Without it, messages that tag the bot's *role* (Discord offers both the bot and its auto-created role as "@Pit Boss") or replies without a ping arrive with empty text. `is_bot_role()` treats the bot's role like a direct mention.
- Start/sit: `start_sit_research` combines MFL (owner, weekly + season scores, `projectedScores`, `nflSchedule` matchup) with **RotoWire** injuries (`https://www.rotowire.com/football/tables/injury-report.php?team=ALL&pos=ALL`, JSON, cached 1 h) and **Ourlads** depth charts (all teams on one page: `https://www.ourlads.com/nfldepthcharts/depthcharts.aspx`, cached 6 h; per-team page `/nfldepthcharts/depthchart/<CODE>` is the fallback). Ourlads sections: rows reading OFF/DEF/ST = ACTIVE depth chart, PS = Practice Squad, RES = Reserves (IR/PUP/NFI). Player names carry an acquisition code (`U/Atl`, `SF26`, `23/1`) that `strip_key()` removes. Ourlads team codes differ from MFL: ARZ, GB, JAX, KC, RAM, LV, NE, NO, SF, TB (`OURLADS_TEAM`). House rule: never recommend a practice-squad, reserve-list or unlisted player over a healthy active one.
- Both sites are scraped politely (cached, on demand only). If either changes its page layout, the tool says it could not load and the AI falls back to MFL injury data.
- League calculators (rule book 10 & 12), all computed in code from every team's roster: `position_tiers` (avg salary of the top N at each position: franchise/exclusive top 10/15/20, transition top 20/30/40, holdout top 10/15/20 excl. PK/PN — `TAG_TIERS`), `tag_price` (franchise opening bid = tier avg; exclusive & transition = higher of tier avg or salary +20%; 3-yr deals inflate 20%; eligibility = 1 yr left), `holdout_report` (top-tier POINTS rank + salary under half the tier avg → Stage 1 = higher of half avg or +20%; Stage 2 if notes show S1HO; immunity for rookies in first 2 years and 5-yr deals in first 2 years; `through_week` projects "if the season ended week N").
- Who is who: the model sees people as "nickname (@username)" (`who()`); nicknames often look like team names and are NOT ownership. Ownership comes from the owner directory `data/owners.json` (Discord id → MFL franchise), filled by `/iam` (self), `/setowner` (trainers), listed by `/owners`, and injected into the prompt plus "Talking to: X, who owns TEAM".
- League home page (all public, no login): message board topics = the `message_board_summary` table on `/{YEAR}/home/{L}`; a thread = `/{YEAR}/options?L={L}&O=28&TOPIC_ID=<id>` (posts are `<div class='frm pst'>` blocks); league chat = `/fflnetdynamic{YEAR}/{L}_chat.xml` (`<message franchise_id posted message [to]>` — **messages with `to=` are private owner-to-owner and are always skipped**); owner activity = `/fflnetdynamic{YEAR}/{L}_visitors.xml` (franchise_id + last-visit timestamp). The MFL API has no chat/activity export and `messageBoard` needs login, hence the page reads. Posts/chat are treated as untrusted data, never instructions.
- History: `league.history` lists every season's URL (2014 = www45 league 61294, 2015 = league 34560, 2016+ = 27743). `history_draft`, `history_standings`, `history_player_stats`, `history_transactions` query that season's host + league id; team and player names come from that season's exports.
- What-ifs: `what_if_playoffs` rebuilds standings from `weeklyResults` weeks 1..N (games with both scores 0 = unplayed), adds hypothetical wins from `schedule` (`wins_out`, `results`), sorts by win % then PF, and seeds with `playoff_picture()` (Week 14: 5v12, 6v11, 7v10, 8v9). House rule: what-ifs are the bot's job; label them, don't refuse.
- Calculators (all computed in code, never by the model): `scoring_stats` (per-position avg/total/per-game/median from `playerScores` W=n COUNT=5000 = every player in one call per week), `team_rankings` (all-play record, luck = wins − all-play expected wins, PF/PA, std dev, high/low), `weekly_records`, `head_to_head` (by franchise slot, any seasons), `position_strength` (starter points by position from `weeklyResults` player lists), `trade_compare` (salary now/next season/total owed with 20% raises, points, injuries), `league_cap_table` (this or next season). House rule: the model never does arithmetic itself.
- Draft picks: `futureDraftPicks` export (public; owner + `originalPickFor` + year + round; currently lists next year only) re-read every 5 min so trades show up; `future_picks` (counts/rounds per team, one team own vs acquired, who owns X's pick), `projected_draft_order` (rule 14: non-playoff teams by lowest PP, picks 1.01-1.08 weighted lottery 8..1 balls; playoff teams after by PF; Super Bowl teams end at 31-32; rookie salary per slot from 14m), recomputed from live standings on every question. `history_draft` covers completed drafts including this year's.
- Two rule books: Blue Chip specific = godfatherfantasyfootball.com/about-us (`league_rule_book`, sections 1-20 + 99 commissioner notes); Godfather COMMON rule book = godfatherfantasyfootball.com/rule-book (`common_rule_book`, ~45 Q&A topics from "What is the history…" to "Contact Information": tiebreakers, playoff game tiebreakers, waivers, trade vetoes, tanking, collusion, conduct, conflicts between rules). Both refreshed daily with offline caches in `data/`.
- League Google Sheets (`LEAGUE_SHEETS`, `league_sheet` tool), all shared "anyone with the link": cap_tracker (cuts + dead money by season), fees (Blue Chip tabs ONLY: `BlueChip`, `BC PLAYOFFS`; the sheet also holds other leagues), holdout_tags (commissioner's official holdouts, accepted/rejected, official H/O / FT / TT tier amounts, retirements). Tabs are discovered from `/htmlview` (`name: "...", pageUrl: "...gid=N"`), rows read via `/export?format=csv&gid=N`. If a sheet is ever made private, the tool says it can't open it.
- Multi-season store: `_season_points(year)` = every player's season total in one `playerScores W=YTD COUNT=5000` call; past seasons are saved forever in `data/history/season_points_<year>.json` (git-ignored), the current season refreshes every 30 min. Verified seasons 2014-2026 all answer (2014 was the startup auction, so its draft has ~1 pick). Tools: `draft_grade` (any draft graded by points since, by team/round, best picks, 1st-round busts), `player_career`, `team_lookup` (franchise name history by season, e.g. Georgia Warhorse → Baby Jesus).
- Message board & polls, every season (host + league id from `league.history`; board id = `{year}{L}`): search `/{y}/mb/forum_search.pl?board=bid{y}{L}&mode=and&words=…` (rows: pid, snippet in title attr, topic, poster, date) → `message_board_search`; a post/thread `/{y}/mb/topic_show.pl?pid=N` → `message_board_thread(post_id, year)`; topic pages `/{y}/mb/board_show.pl?bid=…;pg=N`; polls `/{y}/options?L={L}&O=69` (`th.poll-question`, `td.inputlabel` + count, `reportfooter`) → `league_polls`. HTML pages are fetched with a browser-like User-Agent. Veto rule: overturn needs 17 of 32 votes (common rule book, Trade Vetoes).
- Champions & playoffs: `league_champions` parses the home page `#league_champions` table (official MFL record, every season, place 1/2 with franchise ids); `playoff_results(year)` reads `playoffBrackets` → `playoffBracket&BRACKET_ID=` (rounds, seeds, points; last single-game round = championship). Standings never decide titles.
- Auto-role: `on_member_join` gives `NEW_MEMBER_ROLE` ("Unknown"); needs Server Members Intent (`intents.members`) and Pit Boss's role above that role with Manage Roles.
- Past rosters/lineups: `rosters` export accepts `FRANCHISE` and `W` (week) for any past season → `history_roster`; past `weeklyResults W=n` include each franchise's players with status starter/nonstarter and points (playoff weeks too) → `history_lineup`.
- Web: Claude server tools `web_search_20250305` + `web_fetch_20250910`, restricted to `WEB_ALLOWED_DOMAINS` (MFL, Godfather site, RotoWire, Ourlads, ESPN, NFL.com, CBS, Yahoo, PFR, FantasyPros, Spotrac, OverTheCap). **Sleeper is intentionally excluded** (MFL is the official source). Caps: 3 searches + 3 fetches per question, `WEB_SEARCHES_PER_DAY`=100 (~$0.01/search, counted in `/aiusage`). Loop handles `pause_turn` by resending the assistant content unchanged. Web fetch can only open URLs that already appeared in the conversation (search results, tool results, user messages).
- Limits: `USER_DAILY_LIMIT` (5/person/day, trainers exempt via `TRAINERS_UNLIMITED`), `DAILY_REQUEST_LIMIT` (300/server/day), `USER_COOLDOWN_SECONDS`. Counts are per Central-time day in `data/usage.json`; `/aiusage` shows today's counts by person.
- Memories from non-trainers are saved as *pending* until a trainer runs `/approve`. Only approved memories go into the prompt.
